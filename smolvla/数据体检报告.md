## 数值检查：单位是度，动作为绝对位置

抽第一帧看实际数值：

```
state : -14.154 -104.264  +98.374  +74.945  -11.824  +1.558
action:  -6.813 -104.527  +91.648  +76.044  -12.879  +1.187
```

- 量纲是**度**（不是弧度），量级 −104 ~ +98 符合 SO-101 的 `.pos` 约定。
- `|action[t] − state[t+1]|` 逐关节均值只有 **1.9°**，说明 action 记录的是**下一时刻的绝对关节目标**，不是增量。训练和部署必须保持一致——这也是为什么真机推理时 state 要按同一套关节顺序、同一单位喂进去。
- 夹爪范围 0 ~ 44.9（度），没有出现 0~100 那种百分制，正常。

## 画面检查

抽了第 2 秒和第 8 秒两帧（`_frames/f2s.png`、`_frames/f8s.png`）：

- 机位是**固定第三视角**，不是腕部相机；蓝白色 SO-101 臂和夹爪全程可见。
- 绿色方块放在白色纸片上，在画面中偏小（约 30~40 像素），周围是黑色桌面。
- 背景有纸箱、帐篷、推车等杂物，但**静态**——同场景 56 条，模型容易学到背景捷径，不过不影响先跑通。

## 五个会影响结果的点

1. **单相机**。SmolVLA base 是在"顶视 + 侧视"两路数据上训的，你只喂一路，模型拿不到深度线索，抓取末段（合爪那几帧）会明显吃亏。这是数据决定的，不是参数能补的。想改善只能补一路腕部相机重采。
2. **AV1 编码**。`video.codec=av1`，解码比 h264 吃 CPU。`--num_workers` 要给够（脚本里设了 6），否则 GPU 会等数据。
3. **只有一条任务指令**。`Grab the green cube`，采集/训练/部署三处必须一字不差，包括大小写和没有句号。
4. **没有验证集**。`splits` 只有 `train: 0:56`。想做留出评估，得用 `--dataset.episodes` 只训前 51 条，留 5 条做离线对比。
5. **chunk_size=50 安全**。最短 episode 263 帧，动作块不会跨 episode 边界，不用调小。

## 已经替你定好的参数

```bash
--policy.path=lerobot/smolvla_base
--rename_map='{"observation.images.front": "observation.images.camera1"}'
--batch_size=16        # 单路相机比较省，可先试 32
--steps=15000          # ≈ 12.8 epoch
--num_workers=6        # AV1 解码吃 CPU
```

不需要 `--policy.empty_cameras`：缺的 camera2/camera3 会被源码跳过（`modeling_smolvla.py:391-432`）。
