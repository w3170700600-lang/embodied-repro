# 用 56 条旧 ACT 数据在 A4000 上复现 SmolVLA

> 场景：3090 暂时不可用，只剩杨瑜那台 RTX A4000（16GB）。手上有做 ACT 时采的 56 条遥操作数据（SO-100/101 单臂 6DOF），想复用这批数据把 SmolVLA 跑通一遍。

## 先说结论

**能做，而且是所有方案里代价最小的。** 三条判断：

1. **量够**。SmolVLA 官方推荐 ≥50 条 episode，论文自己的 `svla_so101_pickplace` 是 50 条（5 个方块位置 × 10 次）；官方明确说过 25 条的版本效果明显不行。你的 56 条刚好在推荐线上。
2. **维度对得上**。SO-100/101 的 6 维 state/action 和 `smolvla_base` 的原生维度完全一致，不用改模型（SmolVLA 的 `max_state_dim=32` 也会给短向量补零，但 6 维是"刚好"而不是"凑合"）。
3. **16GB 够用，但要靠默认的冻结策略**。`smolvla_base` 的配置默认 `freeze_vision_encoder=True` + `train_expert_only=True`，只训动作专家。这是 16GB 能跑起来的前提，**不要手动解冻**。

真正的风险不在算力，在**数据格式和相机键名**——也就是下面第 2、3 步。

## 数据集已体检完毕（2026-11-05）

`D:\lerobot-data\so101_test` 已逐项核过，**干净、可开训**。完整证据见 `数据体检报告.md`，要点：

- v3.0 格式，不用转；56 ep / 18794 帧 / 30fps / 一条任务 `Grab the green cube`
- 七个分片的视频帧数与数据行数逐一相等，无截断无丢帧
- state/action 6 维、单位为度、action 是下一时刻**绝对关节目标**（`|action[t]-state[t+1]|` 均值 1.9°）
- **只有一路固定机位 front 相机**——能跑，但抓取末段精度会吃亏
- 视频是 **AV1** 编码，解码吃 CPU，`--num_workers` 要够

## 五步流程

### 0. 在 A4000 上建独立环境（别动杨瑜的 RoboTwin 环境）

```bash
conda create -n smolvla python=3.12 -y
conda activate smolvla
pip install "lerobot[smolvla]==0.6.1"
```

或者直接跑 `bash setup_a4000.sh`，前面这些步骤（含 ffmpeg 系统包、权重下载、GPU 自检）都串好了。

`ffmpeg` 必须有（读视频用）：`sudo apt install -y ffmpeg libavformat-dev libavcodec-dev`。
国内拉权重前先 `export HF_ENDPOINT=https://hf-mirror.com`。

### 1. 拷数据 + 拉权重

```bash
scp -r D:/lerobot-data/so101_test 用户名@a4000主机:~/datasets/    # 约 303 MB
hf download lerobot/smolvla_base                                  # 老版本 CLI 叫 huggingface-cli
```

下不动就是镜像没生效，先解决这个再谈训练。

### 2. 数据体检（已完成，可跳过）

`D:\lerobot-data\so101_test` 已经查过，结论见 `数据体检报告.md`：v3.0、单路 front 相机、6 维对齐、帧数完全对得上。换数据集时再跑：

```bash
python check_dataset.py /path/to/your_dataset
```

### 3. 训练

见 `train_smolvla_a4000.sh`，参数已按你这批数据填好（`rename_map` 只映射 front→camera1，`num_workers=6` 应对 AV1），只需确认 `DATASET_ROOT`。先冒烟：

```bash
STEPS=200 BATCH=8 bash train_smolvla_a4000.sh
```

loss 在 20 步内从 1.x 开始下降、显存稳定不涨，就说明链路通了。然后跑正式：

```bash
STEPS=15000 BATCH=16 bash train_smolvla_a4000.sh
```

**batch 与步数的换算**：56 条 × 约 300 帧 ≈ 1.7 万帧，batch 16 时 1 epoch ≈ 1000 步，15000 步 ≈ 15 epoch。如果 OOM 降到 batch 8，steps 要翻倍到 30000 才是同样样本量。先跑 200 步量一下 s/step，再决定总步数——不要凭感觉填。

### 4. 评估：这是 A4000 方案最大的短板

你现在**既没有 3090 也没有接机械臂的自由**，所以闭环真机评测暂时做不了。三个替代方案，按可行性排序：

- **离线 open-loop 评估（今天就能做）**：留出 5 条 episode 不参与训练，让模型对每帧预测动作块，算预测动作与真值的 MAE / 相关系数，并把预测轨迹和真值轨迹画在同一张图上。这不是成功率，但能明确区分"学歪了"和"学到了"。
- **接 RoboTwin 仿真（要杨瑜配合）**：用 `XPolicyLab` 那套适配把 SmolVLA 接到仿真里跑闭环，但 SO-100 真机数据和 RoboTwin 的观测空间对不上，迁移价值有限，不推荐为此花时间。
- **等 3090 回来再上真机**：`lerobot-rollout --policy.path=<你的 checkpoint>`，注意 `--task` 的字符串必须和采集时**一字不差**。

### 5. 交接给杨瑜时需要说清的三件事

- 用独立的 `smolvla` conda 环境，不碰 `robotwin` 环境；
- `--num_workers=4` 就够，别开 16，会抢他仿真任务的 CPU；
- 训练完把 `outputs/train/smolvla_56ep/checkpoints/last/pretrained_model/` 整个目录拷走——里面有 `config.json`、`model.safetensors` 和归一化统计量，缺一样都加载不了。

## 六个会毁掉训练的坑

| 坑 | 症状 | 处理 |
|---|---|---|
| **相机键名没映射** | 0.6.x 直接报 `feature mismatch` 退出（我上一轮说的"静默"是旧版行为，以官方为准） | 加 `--rename_map` 把 `top/wrist` 映射到 `camera1/camera2`；顺序要跟视角语义对应 |
| **拿官方 Colab notebook 当微调** | 训出来和 base 完全不是一个东西 | notebook 里是 `--policy.type=smolvla`（从零建 config），必须改成 `--policy.path=lerobot/smolvla_base` |
| **数据是 v2.0 格式** | 报错或读到 0 条 episode | 用官方 v2→v3 脚本转副本 |
| **single_task 字符串不一致** | 训练正常，真机上完全不响应指令 | 采集、训练、rollout 三处字符串必须完全相同 |
| **state 定义前后不一致** | 离线指标尚可，真机动作幅度离谱 | 训练和推理必须同一套关节顺序、同一套单位（弧度 vs 度） |
| **日志参数用错版本** | `unrecognized arguments: --trackio.enable` | 0.6.x 用 `--trackio.enable`，旧版换 `--wandb.enable` |

## 时间预算（保守估）

- 环境 + 权重下载：1~2 小时（国内网络是变量）
- 数据体检 + 格式转换：0.5~2 小时（取决于是否要转 v3）
- 冒烟 200 步：10 分钟
- 正式 15000 步：**先量 s/step 再算**。A100 上 20k 步 batch 64 约 4 小时，A4000 是它的 1/3~1/4 算力、batch 又降到 1/4，量级上是"一个通宵"，但必须以实测为准。

## A4000 上踩到的四个坑（都已解决）

1. **`--policy.repo_id` 是必需的**。`policy.push_to_hub` 默认 `True`，不关就报 `'repo_id' argument missing`。加 `--policy.push_to_hub=false` 即可。
2. **SmolVLM2 主干要单独下**。`hf download lerobot/smolvla_base` 只有策略权重，不含 `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`，不补就会在加载模型时建连失败。补下时 hf-mirror 会撞限流，等两分钟重试即可。
3. **torchcodec 加载不了**（`libavutil.so.56` 缺失，系统没装 ffmpeg）。lerobot 会自动回退到 pyav，但显式写 `--dataset.video_backend=pyav` 更稳，也别再折腾 torchcodec。
4. **学习率调度步数要跟 steps 对齐**：config 默认 `scheduler_decay_steps=30000`，只跑 15000 步会在 lr 5e-5 处停下、没退火完。加 `--policy.scheduler_decay_steps=$STEPS`。

## 本机 3050 部署实测（2026-11-06）

结论：**本机直跑够用，不需要远程推理。** 环境在 `D:\smolvla-env`（Python 3.12 + lerobot 0.6.1 + torch 2.7.1+cu118），checkpoint 在 `D:\smolvla-ckpt\pretrained_model`。

关键：**不用升显卡驱动**。driver 512.28（CUDA 11.6）装 `torch==2.7.1+cu118` 即可，CUDA 11.x 次版本兼容；lerobot 只要求 torch>=2.7。

| 指标 | 值 |
|---|---|
| 显存峰值（torch 统计） | **0.90 GB / 4.0 GB** |
| 纯推理 p50 / p90 / p99 | 303 / 332 / 375 ms |
| 完整单步（取帧+预处理+推理+后处理） | 322 ms（其中取帧预处理 19 ms） |
| 模型加载 | 19.7 s |
| GPU 温度 | 53 °C |

`n_action_steps` 选型（30fps）：

| steps | 预算 | 余量 | 判断 |
|---|---|---|---|
| 10 | 333 ms | 1.0× | 临界，p99 会超，不用 |
| **20** | 667 ms | **2.1×** | **推荐** |
| 30 | 1000 ms | 3.1× | 保守，开环窗口偏长 |

两个 Windows 专属坑：`av 19.0.2` 删了 `av.option` 子模块（lerobot 导入即崩）→ 降 `av==15.1.0`；`hf download --include "*.json"` 会漏 `preprocessor_config.json` 和 tokenizer 系列，必须显式列文件名。
